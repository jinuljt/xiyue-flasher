Agent 发布包接口 v1

Agent 发布流程需准备一个固定版本目录，无运行时凭证与用户状态。包含 Agent 可执行文件、完整 console 静态资源、Wiki、出厂 abilities。Flasher 不从相邻仓库自动取最新文件，不下载或执行二进制。目录交付优先；若通过 ZIP 分发，由用户先解压后核对，Flasher 不实现压缩包解压。

release-stage/
  agent/xiyue-agent
  console/index.html  （及完整脚本、样式等）
  console/help.html   （及 Wiki 资源）
  abilities/manifest.schema.json （及出厂能力）
  release.json
  release.sig

examples/release-spec.json 是发布元数据模板，必须替换示例版本。schema: 1、version、profile、userspace_target 和恰好四个 components：agent、console、wiki、abilities。每个 component 记录固定 version（建议 commit）及一个已纳入清单的入口 path。最终 files 列出目录内所有内容文件的 path、非负 size（字节数）、小写 SHA-256。入口可自定，Wiki 可以由 Console 仓库提供并独立记录版本。

发布者先在目录外准备 spec（files 留空）。seal-release 自动清点目录、生成清单并签名，不覆盖已有 release 元数据。签名输入只从标准输入读取 base64 编码的 64 字节 Ed25519 私钥；应由受控密钥设施在内存中传入，不将密钥放进命令参数、仓库或输出。此仓库没有生产私钥或生产信任公钥，也没有调用凭证服务。

# 由密钥设施通过 stdin 注入；不要把私钥直接键入命令行
xiyue-flasher seal-release --release ./release-stage --spec ./release-spec.json

release.sig 为 base64 Ed25519 签名，签名对象是 release.json 的完整原始字节（包括末尾换行）；不做 JSON 重排。公钥文件内容为 base64 编码的 32 字节 Ed25519 公钥。用户必须通过独立可信渠道取得公钥；不从发布包读取自声明公钥。验签后检查档案、四组件与全目录摘要，拒绝多余文件、缺文件、错误长度、摘要变化、符号链接、路径穿越、Windows 特殊路径和大小写冲突。

工作区发布脚本使用同一接口生成了 ARMv7 签名应用包，并通过离线预检。签名验证证明“持有对应私钥者签署过这些字节”；不会证明 ELF 架构、模型/语音可用、许可证、漏洞安全、版本新旧或真机兼容。生产发布仍需独立的可信公钥分发、发布审批与真机验证；不能把示例或测试用随机签名当作正式发布。

与 OH2P 设备档案核对的固件仍使用同一参考身份。对于已验证能运行静态 ARM64 程序的内核，应用包可声明 aarch64-linux。发布及验证同时核对 Agent 的 ELF 架构和静态加载要求。

应用备份与恢复核对

backup 仅复制指定应用目录到一个不存在的新目录，生成 snapshot.json，并立即逐文件读回核对。备份目的地必须在源目录外；拒绝已有目录，失败时删除本次创建的不完整目录。源目录请先停写，以免变化导致核对失败。macOS/Linux 使用私有目录和文件权限；Windows 备份位置仍需用户确认 NTFS ACL。

snapshot 的 schema 为 1，scope 必须是 application-files-only，profile 为当前档案，files 与发布文件清单格式相同。verify-backup 核对备份目录；check-restore 先核对备份，再核对用户已经恢复到另一目录的文件，不覆盖任何文件。恢复目录应只包含快照内的应用文件，不包含 snapshot.json。

备份摘要用于检测意外损坏，并非备份来源签名；能同时修改 snapshot 和数据的人可重算摘要。不要用它认证不可信备份。它不包含分区布局、启动链、设备标识绑定或硬件恢复演练；也不提供系统镜像、凭证导出策略或密钥迁移。对真实应用状态的备份可能含隐私/凭证，仅放本地受保护目录，禁止入库。测试仅使用临时合成文本。

图形预检

Windows 发布包包含 start-wizard.cmd。解压后双击，浏览器会打开本机预检页面。依次选择或填写设备资料 JSON、签名应用包目录、独立来源的验签公钥文件及应用备份目录。离线预检通过也需要进行真实设备身份、安装和恢复验收。命令行可使用 xiyue-flasher wizard 启动同一页面。

设备安装后，请直接打开音箱控制台。首次管理员设置和日常管理均由音箱提供。

应用更新与回退

stage-app 将签名并校验通过的版本复制到应用目录，返回按发布清单计算的版本编号。activate-app 重新核验并切换当前版本。rollback-app 验证并切回上次版本，resolve-app 返回当前版本目录。均需给出 -app-store 和可信公开验签密钥 -trusted-key。应用数据须单独保存，激活时不能并行运行多个安装操作。服务接入、断电保护和真实系统分区恢复仍需设备验收。
